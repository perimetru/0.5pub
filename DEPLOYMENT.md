# Публикация 05pub.md

Публичные файлы сайта находятся только в `site/`. Ветка `gh-pages` должна содержать только эту папку. Резервная копия RestoFlow, исходные техкарты и служебные архивы не должны публиковаться.

## GitHub Pages

В репозитории perimetru/0.5pub: Settings → Pages → Build and deployment → Deploy from a branch → gh-pages → /(root). Custom domain: 05pub.md. После успешной проверки DNS включить Enforce HTTPS.

Если GitHub сообщает, что Pages недоступен для частного репозитория на текущем тарифе, не делайте этот репозиторий публичным: в нём есть резервная копия внутренних данных. Используйте отдельный публичный репозиторий только с файлами сайта или хостинг для статических сайтов.

## DNS для GitHub Pages

В зоне DNS домена 05pub.md создайте четыре записи A для корня (@):

- 185.199.108.153
- 185.199.109.153
- 185.199.110.153
- 185.199.111.153

Для www: CNAME → perimetru.github.io (без схемы и пути).

Записи надо создавать у провайдера, чьи nameservers назначены домену. Покупка домена сама по себе не подтверждает наличие редактора зоны DNS у регистратора. Сначала проверьте панель nic.md. Удалять существующие почтовые и другие записи не нужно. Конфликтующие записи корня должны быть проверены перед изменением.

## Обновление после изменений сайта

Из /workspace/0.5pub, после коммита изменений site/ в main:

```sh
git fetch origin
python3 tools/update_pages_branch.py
git push origin gh-pages
```

Не используйте force push. При наличии отдельной истории gh-pages проверьте её перед обновлением. Наличие ветки и CNAME не доказывает включение Pages, готовность DNS или выдачу HTTPS-сертификата. Проверяйте ответы 05pub.md и загрузку menu.json и изображений после включения публикации.
