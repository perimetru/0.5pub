# 05pub: синхронизация меню и заявки на бронь

## Админка сайта

Вход: `https://05pub.md/admin.html` (ссылка «Администратор» внизу сайта). Перед публикацией новой версии Worker примените `cloud/schema.sql` к существующей D1; `CREATE TABLE IF NOT EXISTS` сохраняет данные. Задайте отдельный случайный `ADMIN_TOKEN` минимум из 32 символов через `wrangler secret put ADMIN_TOKEN`. Ключ синхронизации RestoFlow не даёт доступа к админке, а ключ админки не даёт доступа к броням и резервным копиям. Не помещайте ключ в Git или публичные файлы. В браузере он хранится только в памяти до выхода/перезагрузки.

В «Что показывать гостям» снимите галочку с ненужной позиции и сохраните. Скрытие действует на всё меню, пивные карточки и подбор для компании; запись в RestoFlow остаётся. Вернуть блюдо можно той же галочкой. Новые позиции из RestoFlow по умолчанию видны. Настройки сохраняются в отдельной таблице `website_settings` по стабильным ID, поэтому синхронизация меню их не перезаписывает.

В «Меню для компании» включите свой список для нужной группы, отметьте блюда и выберите блюдо по умолчанию. Выбранные блюда задают порядок начального подбора. Для замены и добавления гостю доступны все нескрытые и имеющиеся блюда соответствующих категорий, независимо от списка рекомендаций администратора. Каждая группа показывает только блюда соответствующих категорий RestoFlow; овощные гарниры отнесены к группе «Картофель и другое». Для выбранных блюд задайте количество отдельно на 4, 8, 10 и 12 гостей: порции, штуки целых блюд или граммы весовых. Пустое поле включает автоматический расчёт. Выключение своего списка отключает и пользовательские нормы количества. Пустой список отключает группу; выключение своего списка возвращает стандартные правила. Скрытые и отсутствующие блюда исключаются. Цены и наличие всегда приходят из RestoFlow.

Сайт применяет изменения при открытии и раз в минуту. При первом открытии гостевой страницы каталог показывается только после ответа облака: локальная копия не должна возвращать скрытые позиции. Если связь пропала после успешной загрузки, остаётся последнее полученное меню с предупреждением. Автономные файлы в `downloads/` — прежние снимки и не поддерживают новые настройки.

## Закрытые резервные копии R2 (RestoFlow 0.1.78)

Подготовлена привязка `BACKUPS` к закрытому bucket `restoflow-backups` класса Standard. Перед публикацией нужно активировать R2 в панели владельца, создать bucket и убедиться, что Public Development URL и Custom Domains не включены. После этого опубликовать Worker: `npx wrangler deploy --config cloud/wrangler.jsonc`. Код находится в `backups.mjs`; до создания bucket эту конфигурацию не публиковать.

Все маршруты `/sync/backups` требуют существующий `SYNC_TOKEN`; публичного доступа и CORS для копий нет. `PUT /sync/backups/restoflow-{hourly|daily|shift|manual}-YYYY-MM-DD-HH-MM-SS.json.gz` принимает gzip до 16 МиБ с заголовком `x-backup-sha256`. R2 проверяет SHA-256, Worker подтверждает размер и метаданные после записи. За день хранится последняя версия, старшая версия не заменяется младшей, после успешной записи сохраняются последние 30 дневных объектов. Одна ежедневная копия обновляется при создании очередной локальной почасовой/ручной/сменной копии; это не 30 неизменяемых версий в течение дня. Список и скачивание доступны через GET `/sync/backups` и `/sync/backups/YYYY-MM-DD`.

В RestoFlow: администратор → резервные копии → Cloudflare R2 → включить → «Сохранить и проверить». По умолчанию отправка выключена. Используется отдельный существующий `data/website-connection.json`. Статус/включение хранятся в `data/cloud-backups.json`. Ошибки повторяются раз в минуту; при выключенном компьютере отправки нет. Скачанный файл проверяется по SHA-256 и читаемости gzip/JSON; восстановление выполняется существующей формой с сохранением текущей базы перед заменой. Рабочую базу ради проверки не восстанавливать: пробное восстановление проверено на отдельной тестовой базе.

Архив содержит базу данных, включая настройки и PIN-хеши, но не фото, программу и отдельный ключ подключения к сайту. Для переноса компьютера нужны также программа, медиа и безопасно сохранённый ключ. Не публиковать резервные копии или ключи в GitHub/на сайте. Ограничение 16 МиБ на сжатый объект ограничивает этот набор из 30 файлов примерно 480 МиБ, однако бесплатный объём Cloudflare общий на аккаунт и не является запретом оплаты превышений.

Сайт остаётся на GitHub Pages. Worker и D1 принимают заявки, пока компьютер ресторана выключен. RestoFlow 0.1.76 получает их исходящим HTTPS-запросом раз в минуту, сохраняет локально и лишь затем подтверждает доставку. Повторная доставка не создаёт дубль.

## Публикация

Нужны Node.js 24+ и официальный Wrangler. Идентификаторы аккаунта и созданной базы заданы в `wrangler.jsonc`.

```sh
npx wrangler login --scopes account:read user:read workers_scripts:write d1:write
npx wrangler d1 execute 05pub --remote --file schema.sql
npx wrangler deploy
npx wrangler secret put SYNC_TOKEN
```

`SYNC_TOKEN` — случайный секрет минимум из 32 символов. Один и тот же ключ вводится в Cloudflare и в настройках RestoFlow. Не добавляйте его в исходники, `connection.json`, коммиты, сообщения или архив обновления.

В `site/connection.json` укажите только публичный URL Worker, например `https://05pub-api.<subdomain>.workers.dev`. Проверка `/health` должна вернуть `configured: true`. Перед публикацией формы выполните пробную отправку и проверьте поступление заявки в RestoFlow.

## RestoFlow

Установите подготовленное обновление 0.1.76 через существующую страницу обновлений. Войдите администратором → «Брони» → укажите URL и ключ, включите синхронизацию. Ключ хранится отдельно в `data/website-connection.json`; публичные ответы API его не возвращают. При переносе на другой компьютер подключение нужно настроить заново. Не добавляйте этот файл в публичный репозиторий.

Администратор и бармен видят заявки, звонят гостю и подтверждают бронь с выбором стола и длительности (по умолчанию 120 минут). Пересекающиеся подтверждённые брони одного стола запрещены. Брони не открывают кассовый заказ и не блокируют продажу за столом. Подтверждение сотрудником не отправляет SMS или сообщение гостю — используется указанный в форме обратный звонок.

## Меню

Публикуются только активные категории и позиции, цены, единицы и доступность. Посуда и упаковка исключены по существующим стабильным ID. Данные сотрудников, продажи, склад и себестоимость не экспортируются. Изменения отправляются в облако раз в минуту; открытая страница сайта обновляет меню раз в минуту. Фото, описания, аллергены и английские переводы сохраняются по ID. Для новых/переименованных позиций без английского перевода используется румынское/русское название. При недоступном обработчике сайт показывает сохранённое `menu.json` с предупреждением; форма не сообщает об успехе, пока облако не подтвердит сохранение.

## Заявки и ограничения

Имя, телефон, дата, время по Кишинёву, число гостей, предпочтительная зона и пожелания. Сервер проверяет поля и согласие, не принимает прошедшее время и даты дальше 90 дней. Повтор неизменённой формы использует тот же UUID. Ограничение — 5 новых заявок в час с одного IP; есть скрытое поле против простых ботов. Это ограничивает и гостей одной общей сети. Для больших групп/ошибок указан телефон. Это базовая защита; при массовом спаме добавьте Turnstile.

Публичного списка броней нет. Секрет нужен для получения очереди и изменения меню. Доставленные облачные заявки старше 90 дней удаляются при приёме следующей заявки; недоставленные сохраняются. Локальная история остаётся в резервных копиях RestoFlow.

## Проверки

```sh
node --test cloud/worker.test.mjs
npx wrangler deploy --dry-run
```

Тест использует встроенный SQLite Node.js, проверяет SQL, права, лимиты, дубли и очередь. Тесты RestoFlow находятся в обновлённом проекте: `test/website-sync.test.js` и `test/website-api.test.js`.

На GitHub Pages публикуется только `site/`. Не публикуйте служебные файлы и резервные копии RestoFlow.
